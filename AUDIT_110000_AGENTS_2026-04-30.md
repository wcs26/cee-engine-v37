**5 modules entiers sans `@require_auth`** : `dossiers.py` (8 routes), `tunnel.py` (14 routes), `post_signature.py` (6 routes), `documents_client.py` (3+ routes), `integrations.py` `/admin/refresh-fiches` (commentaire admet le retrait).

**`verify_mode = ssl.CERT_NONE`** dans `monday_sync.py`, `api.py`, `integrations.py` (3 endroits) → MITM trivial sur tokens sortants Monday/Anthropic/OpenAI/Yousign/ADEME.

**`portail.py:33`** fallback hardcodé `"dev-secret-change-me"` si secret absent (alors que dossiers.py lève `RuntimeError` correctement).

**Pas de rate-limit dédié `/auth/login`** : seul rate-limit global 300/min/IP + sleep 0.3s sur fail. 300 essais/min × IPs distribuées = brute-force possible.

**`/ai/*` sans auth obligatoire** : protégé par `_ai_origin_guard` + rate-limit IP. `CEE_AI_REQUIRE_TOKEN=1` est codé mais pas activé en prod par défaut → abus crédits LLM possible.

**Webhook Monday accepte secret en query string** `?token=...` (loggé par Fly edge proxy logs).

**Bonnes pratiques notées** : PBKDF2-SHA256 120k iters ✓, JWT validé ≥32 chars ✓, headers défensifs (X-Content-Type-Options, X-Frame-Options, Referrer-Policy) ✓, force_https ✓, Dockerfile user non-root ✓, compare_digest partout ✓, pas d'eval/os.system ✓, pas de SQL ✓.
